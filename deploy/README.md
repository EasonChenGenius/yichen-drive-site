## 部署结构

浏览器 → HTTPS nginx → 私有127.0.0.1:8766 Gunicorn → Flask API适配 → SQLite私有数据目录。
nginx 直接提供119MB左右的本地前端图片和静态文件。后台权限、咨询和评价接口继续使用已验证的服务逻辑。

正式域名服务在大陆服务器开放前需完成ICP备案，域名实名信息与备案主体需相符。公司全称用于正式经营资料及备案主体，前台品牌可以保留 YICHEN Drive。证件和负责人信息由经营者在云服务商官方备案系统提交，不需要先发到聊天中。

## 文件

- `../requirements-production.txt`：已验证依赖锁定版本。
- `../webapp.py`：WSGI适配层和静态/健康入口。
- `../wsgi.py`：生产启动入口，强制要求真实HTTPS origin。
- `gunicorn.conf.py`：一个进程、四个请求线程、私有回环监听。
- `nginx.conf.template`：域名与证书路径待替换。
- `yichen-drive.service`：非root运行、自动重启、限定可写目录。
- `app.env.example`：私有环境配置示例，不含授权码。

## 服务器目录（建议）

- `/opt/yichen-drive/current`：发布的代码，只读运行。
- `/opt/yichen-drive/venv`：生产虚拟环境。
- `/var/lib/yichen-drive`：账号、需求、跟进和邮件队列，仅运行用户可访问。
- `/etc/yichen-drive/app.env`：私有配置，600权限；父目录700。邮件设置可原子保存到这里。
- `/var/backups/yichen-drive`：私有备份，700权限；另行建立经营者控制的异地副本。

需要先建立 `yichen` 系统用户并设置这些目录的权限；不能把数据库和SMTP配置复制到公开dist目录。

## 执行顺序

1. 经营者确认具体域名可注册、云服务器规格和含续费规则的结算报价；由经营者完成购买、企业实名和备案。
2. 在实际Linux服务器创建上述目录、非root服务用户和Python虚拟环境，安装锁定依赖。
3. 上传源码包；选择创建新正式数据库，或在私有环境里明确迁移本地真实数据。测试账号和虚构需求不自动迁移。
4. 配置真实HTTPS origin和邮件服务。`YICHEN_CONFIG_FILE` 指向私有配置文件，不能沿用本机私有文件的公开传输链接。
5. 替换nginx里的YOUR_DOMAIN并配置有效证书。申请证书时先设置仅提供ACME验证的HTTP配置，再启用完整HTTPS配置。正式站点备案完成后再对外服务。
6. 安装并启动systemd服务；后端端口只允许本机访问。公开防火墙只放行80/443，SSH访问范围按经营者控制的来源限制。
7. 经营者在正式域名注册管理员，再从服务器本机执行 `operations.py grant-admin --email 2712723487@qq.com`；注册不能自授管理员身份。
8. 在真实域名完成：咨询提交 → 后台可见 → 邮件实际收到 → 修改状态备注 → 退出后拒绝访问 → 服务重启后记录仍在。
9. 按 `backup-data.py` 建立定期私有备份并在隔离目录完成恢复演练；确认域名/服务器续费提醒。

首版只做咨询和人工确认，不自动收款或确认车辆库存。手机号/邮箱归属验证和找回密码仍待接入；经营者在正式开放注册前决定验证供应商及相应费用。

## 2026-10-15 QA补充

- 当前验收基线：持久磁盘上的SQLite＋同源后端；不要把只读容器的临时目录当作持久数据目录。
- 云同步未独立验收，默认关闭。若后续启用，需验证远端权限、后端可靠同步、幂等、数据告知及恢复；浏览器尽力双写不等于持久备份。
- 静态资源新增压缩发布副本，源图保留；nginx模板含gzip、HTTPS服务器HSTS及基础CSP。WSGI直接访问也压缩文本响应。基础CSP并非严格script-src策略。
- 启动服务会自动创建inquiry_requests幂等表；升级前先备份私有库，重启后验收响应丢失重试只有一条需求和一封提醒。
- 正式域名、证书、备案、SMTP实际送达、日志监控、定时备份与异机恢复仍需在真实服务器验收。本地Lighthouse和模拟邮件不替代这些项目。
