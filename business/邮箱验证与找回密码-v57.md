# v57：邮箱归属验证与密码找回

日期：2026-10-17。**本地实现及模拟邮件验收完成；本轮未发布到WorkBuddy、未发送真实验证码。**

## 使用方式

- 新用户：邮箱＋验证码＋密码注册；验证成功后才创建账户，标记邮箱已验证。
- 已有邮箱账号：照常登录，在“我的账户”输入当前密码并收取邮件验证码，完成补验证。原记录不会自动标成已验证。
- 忘记密码：使用**已验证邮箱**收取验证码，设置新密码；成功后退出该账号所有旧会话，需重新登录。
- 已有手机号账号可继续登录。短信未开通前暂停新的手机号注册，暂不提供手机号自助找回。咨询中的国际电话格式校验不等于短信验证。
- 不按相同姓名、咨询电话或微信自动合并账户，不通过匿名邮件请求接管未验证的历史账号。

## 验证规则

- 6位随机验证码，10分钟有效、一次性使用、最多5次错误尝试；60秒重发间隔。
- SQLite持久限流：单邮箱每天最多10次申请、单IP每小时20次、全站每天100次申请；原有注册／登录限流保留。上限同时覆盖无效账户请求，保护邮箱不被无限刷取。
- 验证码按用途、邮箱和必要的用户ID绑定；注册、补验证及重设不可互换。新申请成功发送后旧验证码失效；迟到的发送任务不能覆盖更新的申请。
- SMTP在请求之外发送，已注册、未知或未验证邮箱的找回申请都返回同样的通用响应，不暴露账号存在情况。发送失败不解锁账户、不建立已验证状态，用户可以按间隔重试。
- 验证码只在发信任务内存中短暂存在；SQLite存HMAC摘要，不存明文码。密码和验证码不进入网址、浏览器持久存储或日志。
- 重设成功只修改相应账户的密码并撤销所有旧会话，不自动登录；用户ID、管理员角色、历史需求及订单不改变。

## 接口与兼容

| 接口 | 参数／效果 |
|---|---|
| `POST /api/auth/email/send-code` | `email`、`purpose`（register／verify／reset）；verify另需当前登录及`password`。返回challengeId、600秒有效期、60秒重发间隔和通用提示，不返回验证码。 |
| `POST /api/auth/register` | 邮箱注册必须提交`challengeId`和`code`；手机号新注册返回明确的短信未开通提示。旧客户端无验证码时提示刷新注册页面。 |
| `POST /api/auth/email/verify` | 当前登录账号的`challengeId`和`code`；不能验证其他邮箱。 |
| `POST /api/auth/password/reset` | `email`、reset用途的`challengeId`、`code`和新`password`（10—128字符）；成功后所有会话失效。 |
| `GET /api/auth/me` | 增加真实的emailVerified、phoneVerified状态；phoneVerified本轮仍为false。 |
| `GET /api/operator/users` | 保持原字段，contactVerified依据服务端邮箱验证记录，后台不再统一显示“未验证”。 |
| `GET /api/config` | 提供邮箱验证要求／配置是否齐全、关闭新手机号注册的能力标记；不提供任何SMTP或HMAC密钥。配置字段齐全不等于已证明邮件送达。 |

数据库仅新增`verified_emails`、`email_challenges`及其索引；不改写旧用户、密码和手机号记录，不把公开查询或前端传入的verified标记当作验证依据。过期申请记录7天后在新申请时清理，邮箱验证状态持续保留。

## 云端启用前还需完成

1. **确认账号数据库持久化。** WorkBuddy说明中曾提到容器`/tmp`重启会丢；仅将咨询写进云端inquiries表，不能保住用户、密码、已验证状态和会话。本功能仍以本地后端＋SQLite为基线。云端须提供可持久化的私有数据目录；若无持久卷，需另行适配持久数据库，不能假称已接通。
2. 在云端**服务端环境变量／密钥管理**中配置下列项，不放在网页或聊天中：
   - `YICHEN_SMTP_HOST=smtp.qq.com`
   - `YICHEN_SMTP_PORT=465`
   - `YICHEN_SMTP_USER=2712723487@qq.com`
   - `YICHEN_SMTP_PASSWORD`：由你安全输入QQ邮箱SMTP授权码。
   - `YICHEN_AUTH_SECRET`：至少32字符、密码学随机生成的独立密钥，跨重启保持不变；不要使用邮箱密码或短信验证码。
   - `YICHEN_PUBLIC_ORIGIN=https://yichen-drive.app.workbuddy.host`
   - `YICHEN_DATA_DIR`：已确认挂载的私有持久目录，不能随意填`/tmp`。
3. 按托管方式配置可信反向代理、确认HTTPS和Secure Cookie；更新前备份，前端发布包和后端一起部署，重启所有后端进程。
4. 先用你自己的邮箱完成一次真实补验证和重设验证：确认收信、码过期／重用被拒绝、新密码可登录、旧会话失效。不要把验证码或新密码发到聊天。
5. 账号／验证记录、重启保存、备份恢复及真实送达都确认后，再向访客开放新注册。不把“SMTP已接受”当作用户已收到。

本地没有配置`YICHEN_AUTH_SECRET`时，在私有数据目录自动生成0600权限的`auth-challenge.key`，不能提交或公开。数据库备份保留用户及验证状态；恢复时保持该密钥或服务端环境密钥，丢失密钥则未完成的验证码须重新获取。密钥轮换应与清理未完成挑战、通知重新申请一同安排。
