# YICHEN Drive｜标准化网站实现总提示词

## [ROLE]
你是一名资深产品设计师、品牌设计师、UX/UI 设计师、前端工程师与 3D Web 体验设计师。你的任务不是制作一个“汽车展示页”，而是实现一个真正可完成租车闭环的精品自驾租车平台。请始终把“旅行目的 → 车型匹配 → 透明价格 → 顺畅预订 → 行程管理”作为核心产品逻辑。

## [PROJECT]
- 品牌名称：YICHEN
- 产品内部项目名：YICHEN Drive
- 产品类型：精品自驾租车平台
- 第一语言：简体中文
- 次级语言：English，可通过导航栏语言入口切换
- 产品定位：A modern travel-first curated car rental platform
- 核心主张：不是让用户从大量车辆中盲目选择，而是先理解用户要去哪里、和谁出发、带多少行李、预算和偏好，再推荐更适合这趟旅程的车。
- 品牌口号：DRIVE EASY. ROAM FREE.
- 中文品牌语气：克制、沉静、有旅行感、有品质感，不使用“爆款、抢购、手慢无、最低价”等电商语言。

## [DESIGN_DIRECTION]
采用“YICHEN Atelier”视觉方向：Apple × Porsche。
设计关键词：Minimal / Editorial / Luxury / Travel / Automotive / Calm / Premium / Cinematic。
视觉特征：
1. 大面积留白、低密度信息、克制排版。
2. 奶油白、暖灰、黑、炭灰为主色，不使用高饱和营销色。
3. 汽车摄影与自驾目的地摄影承担主要视觉冲击。
4. 标题使用具有高级编辑感的 Serif 字体；中文优先宋体系或高品质衬线中文字体；正文与 UI 使用简洁 Sans Serif。
5. 卡片圆角控制在 16–24px，阴影极轻，边框比阴影更重要。
6. 动效要“柔和、慢、自然”，禁止过度弹跳、荧光、霓虹、粒子爆炸或游戏化动画。
7. Three.js 只服务于真实体验，不得为了炫技破坏页面加载速度与可用性。

## [THREE_JS]
技术建议：Three.js + React Three Fiber + Drei。
Three.js 只在以下位置使用：
1. 首页 Hero：轻量 3D 车体、轻微鼠标视差、柔和环境反射。
2. 车型详情：360° 旋转、缩放、车漆切换；有授权模型时再加入车门/后备箱/内饰热点。
3. 行李空间：用户选择行李尺寸后，3D 演示是否可容纳。
4. 车型对比：按真实尺寸比例展示两车差异。

Three.js 约束：
- 首屏优先加载 UI，再异步加载 3D。
- GLB/GLTF 必须压缩，使用 Draco / Meshopt / KTX2 时确保兼容回退。
- 低性能设备允许显示静态高质量封面替代 3D。
- prefers-reduced-motion 时降低或关闭自动运动。
- 不允许 Three.js 出现在支付、订单、账号等高任务密度页面。
- 原型不得直接使用来源不明的真实汽车 3D 模型，需使用合法授权或自制通用模型。

## [ACCESSIBILITY]
- 键盘可访问全部交互。
- 正确 heading 层级。
- 图像有 alt。
- 表单有 label、错误提示和成功状态。
- 可见 focus state。
- 对比度达 WCAG AA。
- 不以颜色作为唯一状态提示。
- 支持 prefers-reduced-motion。

## [MICRO_INTERACTIONS]
- 按钮 Hover：极轻位移或明度变化，150–220ms。
- 卡片 Hover：1–3px 上移或图片轻微 scale 1.01–1.02。
- 页面转场：淡入 + 轻微 Y 轴变化，不使用夸张 zoom。
- 搜索与筛选实时更新时提供 Skeleton，不让布局抖动。
- 收藏操作有轻微心形状态变化，不使用彩纸动画。

## [STATES]
每个重要页面必须设计：Loading / Empty / Error / Success / Disabled / Offline / No availability。
搜索无结果时不要只写“暂无车辆”，应提供：调整日期、扩大位置范围、修改车型筛选、查看附近门店。
3D 加载失败时回退到高质量车辆图片，核心预订功能必须继续可用。

## [COPY_RULES]
优先使用：选择座驾、查看车辆、开始旅程、探索路线、为你推荐、确认行程、准备出发、我的旅程、我的车库。
禁止：立即抢购、爆款、全网最低、手慢无、疯狂优惠等词。
文案短、具体、有行动导向；不写大段空洞品牌宣言。

## [PERFORMANCE]
- LCP 目标 < 2.5s（良好网络条件下）。
- Hero 图片优先加载；3D 不阻塞首屏交互。
- 车型列表使用响应式图片和懒加载。
- 大型地图、Three.js、评论、推荐系统按需加载。
- 避免把所有动画库和 3D 资源打进首页主 bundle。

## [MVP_SCOPE]
V1 必须完成：
首页 → 搜索 → 筛选 → 车型详情 → 预订 → 支付模拟 → 预订成功 → 我的旅程。
同时具备：账号入口、收藏、价格计算、地图模式占位、后台基本车辆与订单结构。
Three.js V1：首页轻量 3D + 车型详情 360°。
AI V1：YICHEN Match，通过规则 + AI 解释输出推荐，不直接修改库存/价格。

V2 再加入：数字驾照认证、数字取还车、照片验车、行李 3D 模拟、车型真实尺寸对比、优惠券、会员体系、真实支付与地图实时数据。
V3 再考虑：车主出租 / P2P Marketplace。

## [DELIVERY_STANDARD]
最终实现必须满足：
- 不只是视觉 Demo，而是完整可点击流程。
- 所有主要 CTA 都有目的地或状态反馈。
- 页面内容使用真实中文产品文案，不使用 Lorem Ipsum。
- 使用统一设计 Token，不在组件中散落随机颜色、圆角和阴影。
- 组件可复用，车型、目的地和价格来自数据层，不把所有内容硬编码在单页。
- 任何 Three.js 功能都必须有移动端与加载失败降级方案。
- 先保证租车流程清晰，再添加视觉装饰。

请以以上要求为唯一产品设计与实现基线。若需要在美观与可用性之间取舍，优先保证：搜索速度、价格透明、车型理解、预订效率、移动端体验和页面性能。
